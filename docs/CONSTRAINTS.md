# 何が動かせて、何が動かせないか

**このファイルは分類のためだけにあります。** 中身の説明は各ファイルにあるので、
ここでは「誰が決めたか」だけを書きます。

なぜ要るか。`CLAUDE.md` も `docs/GOAL.md` も、**オーナーの指示とこちらの判断が
同じ命令口調で混ざっていた。** 後から来た側には、どれが動かせないのか分かりません。
その結果、**見直すべきものを聖域にし、守るべきものを勝手に変える**危険があります。

分類は2つだけです。

- **A. オーナーが指示したこと** — 勝手に変えない。変えたいなら**提案して確認を取る**
- **B. こちらで決めたこと** — **いつでも見直してよい。** 根拠と、覆る条件を併記する

**新しい規則を足したら、必ずここに分類を書くこと。** 書かないと、また混ざります。

---

## A. オーナーが指示したこと（勝手に変えない）

日付は指示のあった日。**言い回しはできるだけそのまま残します。**

| # | 指示 | 日 | どこに効いているか |
|---|---|---|---|
| A1 | **目標**（下に全文。書き換え厳禁）。「操作を頼んでもよいが、読むとは限らない」も本文の一部 | 継続 | `docs/GOAL.md` 冒頭・`CLAUDE.md` |
| A2 | 「公開リポジトリの存在は誰にも教えないで」 | 08-04 | 動画・説明欄・コメント・タイトル。`upload_only.py` の FORBIDDEN 検査 |
| A4 | **恒久指示を忘れないように設計する** | 08-04/08-05 | `scripts/goal_reminder.sh` が UserPromptSubmit / PostCompact で **A をこの表から抜き出して毎回注入** |
| A8 | **トークンは土曜07:00 JST 区切りで週300ドル。ただし週ごとに絞ることがある**（今週は20クレジット） | 08-05 | `status.py` の `WEEK_OVERRIDE`（期限つき・自動失効）・`CLAUDE.md` 原則5 |
| A9 | **終わるときに毎回「終わるのが最善か」を考える** | 08-05 | `scripts/stop_check.sh`（Stop フック） |
| A10 | **自動実行は永久に運用する。止めない** | 08-05 | `docs/TRIGGER.md` |
| A12 | セッションが長くて判断が雑になるのを解決する。それを理由に終わらない | 08-04 | `verify.py` の機械検査・`inspect_build.py` |
| A13 | **あらゆる手段を実行してよい** | 08-05 | 下の「A13 について」 |
| A14 | **この表にあるもの以外は、すべてあなたの考えで変えてよい** | 08-05 | B の全項目。下の「A14 について」 |

### A1 の全文（オーナーの言葉のまま。絶対に書き換えないこと）

> 目標は最短で月収20万を達成することです。最短とは、原理的に最大の理論値で、
> その理論値は空想のものであり、つねに発見、達成はできていないものと考えられます。
> その上で最短を目標としてください。それ以外の制約は一切ありません。あなたが
> できることは全て行っていいです。私側への指示をしてもいいですが、それを私が
> 必ず読むとは限りません

**この表がすべてです。** 過去にオーナーが言った言葉でも、ここに無いものは恒久指示ではありません。
（欠番があるのは、番号を詰めると過去の JOURNAL の参照とずれるため。経緯は JOURNAL にあります。）

### A14 について

**「この表以外は全部あなたが決めてよい」という指示です。** つまり:

- **B のどれも、数字か理由があれば変えてよい。** オーナーに確認を取る必要はない
- **「昔オーナーがそう言ったから」は理由にならない。** 言われた瞬間の指示と、
  恒久的に守るべき指示は別物。**A の表に無いなら、それは恒久指示ではない**
- **A に無いものを A のように扱わないこと。** それが一番よくある壊れ方です

**B を変えたら、理由を `docs/JOURNAL.md` に書くこと。** 承認は要らないが、記録は要る。

### A4 について

**「忘れない」ではなく「忘れないように設計する」。** 記憶に頼るなという指示です。

`scripts/goal_reminder.sh` が毎ターン発火し、**この表の A を機械的に抜き出して**
文脈へ戻します。**手で写さないこと** — 写すと必ずずれます
（実際「週100クレジット」が5ファイルに散った）。**この表を直せば注入も直ります。**

対象は目標だけではなく**恒久指示すべて**です。以前は `GOAL.md` を丸ごと
注入していましたが、**肝心の A が揃っていませんでした**（目標本文はあっても
リポジトリを伏せる・週300ドル・あらゆる手段を実行してよい、が入っていない）。
手順や方法論（B）ばかりが毎回入り、守るべきもの（A）が入っていないのは本末転倒でした。

**A を増やしたら、注入は自動で追随します。** 何もしなくてよい。
ただし**表の書式（`| A番号 | 内容 | 日 | 場所 |`）を崩すと抜き出しが壊れる**ので、
書式を変えたら `scripts/goal_reminder.sh` の正規表現も直すこと。

### A13 について

**これは許可ではなく指示です。** 「やってよい」ではなく「**やれ**」と読むこと。

つまり**自主規制で止まるな**ということ。具体的には:

- **承認を待たない。** できることは黙って実行する（A1 も「私が読むとは限らない」と言っている）
- **手段を狭く見積もらない。** ニッチ・尺・形式・頻度・チャンネル・言語・
  収益の立て方まで、**全部が対象**。いまの構成は出発点であって答えではない
- **「たぶん許されない気がする」で候補から外さない。** 外すなら理由を数字か事実で言う
- **既存の実装を惜しまない。** より速い道が見つかったら捨てる

**手段として成立しないもの**（制約ではなく、**目標を壊すので効かない**）:

- 再生数や登録者の購入、複数アカウントでの水増し、なりすまし、虚偽の数字。
  **見つかればチャンネルごと失う。** 収益化されなければ RPM がいくつでも収入はゼロなので、
  これは倫理の話である前に**期待値がマイナス**
- 法に触れること。同上

**この2つ以外で手を止めていたら、それは A13 に反しています。**
迷ったら実行して、結果を JOURNAL に書くこと。

### 許可されていること（やってもよいが、やる義務はない）

- **チャンネル名を変えてよい**（08-04）。ただし API では変更できない
  （個人チャンネルは `brandingSettings.channel.title` の更新が黙って無視される）。
  Studio が要るのでオーナーの作業になる。**読まれない前提で設計するので、依存しない**

**A1 は「制約は一切ない」と明言しています。** つまり A の表にあるもの以外は全部 B です。
迷ったら B に倒してよい。**聖域を増やさないこと。**

## B. こちらで決めたこと（いつでも見直してよい）

**「なぜ」と「何があれば覆るか」を必ず併記すること。** 理由の書いていない規則は、
次に来た側が判断できず、惰性で残ります。

### B1. 制度を解説せず、自分で計算した結果を発表する

- **なぜ** — YouTube の収益化ポリシーが「他人の資料の読み上げ」「量産テンプレート」を
  対象外と明記しているため。収益化されなければ収入はゼロなので、到達可能性の条件
- **覆る条件** — ポリシーを守る別の形（自分の声、実画面の収録、別形式）のほうが
  速いと分かったとき。**ポリシーは事実だが、守り方は他にもある**
- 詳細は `CLAUDE.md`「この作りの根幹」

### B2. 1本に chart を最低3枚（`verify.py` が落とす）

- **なぜ** — 棒の長さが計算結果なので、回ごとに図の形が変わる。量産判定を避ける
- **覆る条件** — 別の方法で「同じ絵の繰り返し」を避けられると分かったとき。
  枚数そのものに根拠はない（**3 は勘で置いた数字**）

### B3. ショートの1枚目は `stat`、60秒以内、ID は `s-<計算モジュール名>-<連番>`

- **なぜ** — 最初の1画面で離脱が決まると考えたため。IDは calc を自動で引くための規約
- **覆る条件** — 冒頭を chart にしたほうが伸びると数字で出たとき。**未検証**

### B4. 改正が続く数字は「入力」に逃がす

- **なぜ** — `src/calc/jutaku.py` で借入限度額を使わず年末残高を入力にした。
  改正に左右されず、視聴者も源泉徴収票だけで追試できる
- **覆る条件** — たぶん覆らない。ただし**入力が増えすぎると視聴者が離れる**ので、
  そこは実績を見ること

### B5. 目視（contact sheet）はショートだけでよい

- **なぜ** — 画像の Read は高く、長尺は再生数がほぼ0で当たり率が効くのはショートだから
- **覆る条件** — 長尺が伸び始めたとき。**いまの再生数の分布に依存した判断**

### B6. しきい値は掛け算してから置く／検査は壊れたものだけ／故障を注入して発火を確かめる

- **なぜ** — 単色サムネのしきい値をバイト数で勘に置いて素通りさせた。
  登録率の反証条件を100再生に置いて、期待値0.3人で何も検出できなかった
- **覆る条件** — 覆らないはず。これは方法論であって内容の判断ではない

### B7. 律速は登録者（総再生時間ではなく）

- **なぜ** — 門が「登録者1,000人 かつ 総再生4,000時間」で、登録率0.3%なら
  登録者側が約33万再生・総再生時間側が約6万再生。遅いほうで決まる
- **覆る条件** — 登録率が実測で0.3%から大きく外れたとき。
  **8/5 時点で890再生・登録者1人＝約0.11%。まだ n が小さい**

### B8. 公開は19:00 JST、予約は数日先まで埋める

- **なぜ** — 日本の視聴ピークが19-22時とされるため。予約が埋まっていれば
  起きなくても投稿が途切れない
- **覆る条件** — 時間帯べつの実績が出たとき。**19:00 に根拠は無い（一般論）**

### B9. 仮説に反証の期限と条件を切る（`config/hypotheses.yaml`）

- **なぜ** — 期限を切らないと推測が永久に推測のまま残るため
- **覆る条件** — 覆らないはず。これも方法論

### B10. ショートは1日1本に絞る

- **なぜ** — 8/4 に5本を90分で出し、後の3本が8時間0回だった。
  1日に配信される本数に上限があるように見える
- **覆る条件** — **検証中**（`hypotheses.yaml`、期限 8/6）。
  1日1本が配信されるなら律速は当たり率になる

### B11. 常時稼働はしない。定期実行は6時間おきに1回、終わったら終わる

**これはこちらの判断です。間隔も含めて裁量。** 6時間という数字に根拠はない
（予算とのつり合いで置いただけ）。**遠慮せず動かしてよい。**

- **なぜ維持するか — 律速が「私の起きている時間」ではないから。**
  1. **トークン** … 61時間で20クレジット。6時間おき=10回で1回2.0。
     常時稼働にすると1回あたりが激減し、**分析の質が落ちる**
  2. **YouTube の配信** … 8/4 の実測で、90分に固めて出した5本のうち
     後の3本は8時間0回。**本数を増やしても再生は増えなかった**（`hypotheses.yaml` confirmed）。
     起きている時間を増やしても、出せる本数は増えない
  3. **データの到着** … 判定に要る数字は YouTube 側の都合で出る。起きて待っても早まらない
  4. **投稿は予約済みなら起きなくても公開される。** チャンネルは私が寝ていても動く
- **覆る条件**（どれか1つでも満たしたら頻度を上げる）
  - **1日1本の上限が外れたと分かったとき**（`hypotheses.yaml` B10 の判定次第）。
    出せる本数が増えるなら、起きる回数を増やす価値が出る
  - **当たり率を上げる作業が、明らかに時間で買えると分かったとき。**
    いまは「何が当たりを決めるか」自体が分かっていない（n=2）ので、
    時間を注いでも空回りする
  - **予算が大幅に増えたとき。** いま1回2.0クレジットで、これ以上刻むと1回が薄くなる
- **見直す頻度** — 上の3つは全部いま検証中。**数字が出るたびに問い直すこと**

### B12. 分析は毎回やる。作成と公開予定の作成・変更は任意

**これはこちらの判断です。** 考え直したうえで、いまは維持する。

- **なぜ** — 作成を毎回の義務にすると、予約が埋まっていても無理に作って予算を食う。
  分析だけは毎回要る。**数字を見ないと B の各項目を見直す機会が来ない**ため
- **覆る条件** — 「分析しても変えることが無い」回が続いたとき。
  そうなったら分析すら任意にして、**予約が切れそうなときだけ起きる**形にしてよい

## 迷ったときの決め方

1. **A にあるか？** あるなら変えない。変えたいならオーナーに提案する
2. **無いなら B。** 根拠と覆る条件を確かめ、数字がそれを覆しているなら**変える**
3. どちらか判断できない新しい話が出たら、**A1 の「制約は一切ない」に従って B に倒す**

**B を変えたら、このファイルの当該項目と `docs/JOURNAL.md` を必ず直すこと。**
