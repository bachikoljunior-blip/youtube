## 正しい意味

Anthropic の公式仕様では、対象プランに含まれる Fable 5 / 5.1 は、**通常の週間使用上限のうち最大50%分**まで利用できます。これは追加の50%が付くという意味ではなく、Fableも他モデルと同じ通常の週間枠を消費します。

公式説明: https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan

画面の2本の目盛りは、次のように読むこと。

- **「すべてのモデル」100%**: Fable・Opus・Sonnet・Haiku等を合算した通常の週間上限。
- **「Fable のみ」100%**: 上の通常週間上限の**50%分に相当するFable専用の内訳上限**を使い切った状態。

したがって、次の2つは誤り。

1. **「Fable のみ」が50%になったらFableを止める** —— 誤り。専用目盛りは100%まで利用可能。
2. **「すべてのモデル」が50%になったらFableを止める** —— 誤り。全モデル50%の中身がFableとは限らない。Fableの到達判定は「Fable のみ」の目盛りで行う。

正しい利用可能性の門は、原則として次です。

```text
Fable のみ < 100%  → プラン内のFable枠は残っている
Fable のみ >= 100% → プラン内のFable枠を使い切った
```

「Fable のみ」100%は、通常の全モデル週間上限の50%分をFableに使ったという公式上限です。**オーナーが独自に置いた50%制限ではありません。**

## 目標最適化とは分ける

Fable枠が残っていることは、Fableを使える条件です。**Fableを必ず使う理由ではありません。**

模型は仕事ごとに、次を比較して選ぶ。

- YouTube収益月20万円への期待効果
- 判断の不確実性
- 間違えたときの損失
- その判断が今後の何本へ効くか
- 使用量

定型・可逆・機械的な仕事は軽い模型で足りることがあります。企画、仮説検証、形式選定、次の1本の設計など、目標到達日を大きく動かし得る仕事には強い模型を優先します。

## 現行コードへの即時適用

既存の `scripts/quota.py` は `fable_percent` を **50** と比較しており、メーターの意味を取り違えています。また、Fable専用目盛りを全モデルの消費速度で外挿しています。どちらも模型選択には使いません。

親は当面 `python scripts/next_round_owner.py` を使うこと。このラッパーは、

- 「Fable のみ」の上限を100%として扱う
- 全モデルの速度でFable専用目盛りを外挿しない
- 100%未満／以上だけをFableの利用可能性の門として返す

ように補正します。

これは**利用可能性の補正**であり、仕事別の模型最適化そのものではありません。仕事別の選択理由は `docs/OWNER_INSTRUCTION_GATE.md` に従って残すこと。
