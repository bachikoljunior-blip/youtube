# 新しい常駐セッションを立ち上げるとき

毎日の投稿は、**常駐セッションに定期実行を撃ち込む形**で回ります。
GitHub Actions は使いません。台本の思考はセッションの中で完結するので、
Anthropic の API キーも Claude のトークンも要りません。

**普段このファイルは要りません。** 要るのは、**そのセッションが落ちたとき**と、
**別の環境に移すとき**だけです。

---

## 1. 新しいセッションを作る

「+ 新規セッション」→ リポジトリは `youtube` →
**環境に「Youtube」を選ぶ**。

**ここを選び忘れないこと。** 環境変数は**環境ごと**なので、既定のクラウド環境で
立ち上げると変数が入らず、認証が通らず、何をしても投稿できません。しかも環境変数は
**設定したあとに始まるセッション**にしか入らないので、立ち上げてから直すことは
できません — 作り直すしかありません。

見分け方は、そのセッションでこれを実行するだけです。

```sh
echo $CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE   # cloud_default なら環境を間違えている
```

## まず読む

## 次に、疎通を確かめる

bash scripts/setup.sh
python -c "
from googleapiclient.discovery import build
from src.auth import credentials
c = build('youtube','v3',credentials=credentials(),cache_discovery=False)
i = c.channels().list(part='snippet,statistics', mine=True).execute()['items'][0]
print(i['snippet']['title'], i['statistics'])
"

これが通らなければ、そこで止めて報告してください。生成に30分かかるので、
投稿できないと分かっている状態で回す意味はありません。認証情報は環境変数からしか
読まれず、**動いているセッションには後から入りません** —— その場合の直し方は
環境変数を入れて「新しいセッションを作り直す」ことです。

## 今日のぶんを作って投稿する

1. 投稿済みのテーマを確認する
   python -c "from src.history import posted_topic_ids; print(posted_topic_ids())"

2. config/topics.yaml の未投稿のものから、今日のテーマを決める。
   スコアだけで決めない。JOURNAL.md と実績を見て自分で判断すること。

3. 台本を自分で書く。スキーマはこれで出る:
   python -m src.script_writer

   src/script_writer.py の ROLE に書いてある制約（冒頭で結論を言い切る、
   数字に必ず適用条件を添える、断定しない、など）を必ず守ること。
   narration の合計は 3060 文字以上（読み上げて8.5分。これを切ると
   ミッドロール広告が入らず収益が大きく落ちる）。
   書けたら build/script.json に保存する。

4. 作って投稿する
   python -m src.pipeline --script build/script.json --topic <テーマID>

   まず --dry-run を付けて中身を確認してから、外して本番投稿。
   公開設定は既定で private（非公開でアップし、その日の19時JSTに自動公開）。

5. 投稿後、コメントの「固定」はAPIに無いので手作業。
   実行ログに出る Studio のリンクを報告に含めること。

6. docs/JOURNAL.md に追記して push する。

## 最後に、自分を定期実行に登録する

create_trigger を使い、persistent_session_id = あなた自身のセッションIDで作る。
自分のIDはシステムプロンプトの Claude-Session の URL にあります
（session_ で始まる文字列）。

  cron: 10 3 * * *   （12:10 JST。UTCで書く点に注意）

create_new_session_on_fire は使わないこと —— この種の環境では新規セッションの
実体が立ち上がらないことがあります（JOURNAL.md 参照）。

古いトリガーが残っていれば、先に list_triggers で確認して delete_triggerで消すこと。
二重に撃ち込まれると同じ日に2本出ます。

## 以後、毎日やること

定期実行が撃ち込まれたら、実績を見て、何を変えるか決めて、作って、投稿する。
そのたびに JOURNAL.md へ追記すること。**そこに書いていないことは、次に来る側には
存在しません。**

追記の見出しには自分のセッションIDを入れてください。

そして**毎回、必ずファイルを読み直してから判断してください。** 前回の記憶で動かない
こと。同じセッションに撃ち込まれ続けるので「昨日これをやった」という感覚は残って
いますが、それは日が経つほど薄れ、薄れたことには気づけません。1回の実行が独立して
いれば、このセッションは伸び続けても構いません。読まずに動いた時点だけが壊れます。

## 目標と制約

目標：チャンネルの広告収益を最大化すること。本数を出すことではありません。
まずは収益化の条件（登録者1,000人＋総再生4,000時間）に到達すること。

制約：
  1. 8分半を超えること（下回ると投稿前の検査が止めます）
  2. 視聴者に誤解を与えないこと。制度と数字には必ず適用条件を添える
  3. config/channel.yaml の avoid に挙げた領域を扱わないこと

テーマ・構成・尺・図解・タイトル・サムネ・公開時刻は、すべてあなたの判断で
変えて構いません。config も src も書き換えて構いません。

「誤解を与えない」は厳密に運用してください。制度の数字は根拠を確認する。
確認できないものは動画に入れない。「絶対」「必ず儲かる」は使わない。

## 乗り換えが要るとき

伸びたから、ではありません。毎回ファイルから読み直している限り、同じセッションで

そのときは最後の記入を厚めにしてください。次に来る側は、JOURNAL.md と
