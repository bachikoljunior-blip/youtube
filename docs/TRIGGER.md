# 自動実行（トリガー）の正本

**この運用は永久に続けるものです。** 止めない。人が思い出して直す前提にしない。

自動実行はこのリポジトリの外（Claude Code の Routine）にあるので、壊れたり消えたり
したときに**中身をここから復元できる**ようにしてある。トリガーの設定を変えたら、

**定常は6時間おき（週28回）。** 予算は**週間使用量の%**で見る。
定常15% なら1回あたり約0.5%。**1応答 ≒ 0.007%**（実測の高いほう）。

**単純なトークン数では測れない。** 種類ごとに重みが違う（出力5・キャッシュ書1.25・
入力1・キャッシュ読0.1）。換算は **1% = 重み付き 11M**。
較正の経緯は `scripts/usage.py` の docstring。
**1%あたりの値は、小さいほうが安全側**（消費を多めに見積もる）。

> **高いのは出力。** 文脈が積もるとキャッシュ読みは膨らむが、そこは安い。
> 律速は「文脈の長さ」より **「どれだけ書いたか」**。

## 間隔を変える判断

    残り% ÷ (残り時間 ÷ 6) = 1回あたり使える%
    1応答 ≒ 0.007%（実測）。つまり 0.07% ≒ 10応答

**1回あたり0.1%（≒10応答）を下回るなら、日次に落とす。** 上回るなら6時間おき。

ただし**まず疑うのは頻度ではなく1回の長さ**。通常の自動起動は10〜20応答で収まる。
超えるのは長い対話・同じ確認の繰り返し・画像の Read。**そちらを削るほうが先。**

## 落としても止まらない理由

**投稿が予約済みなら、起きなくても公開される。** だから間隔を落としても
チャンネルは動き続ける。逆に**予約が切れそうなときは、他を削ってでも生成に使う。**

`status.py` が「予約が入っていない日」を出すので、そこだけ見ればよい。

## トークン予算

**土曜07:00 JST 区切りで、定常は週間使用量の15%。単位は%（ドルではない）。**
`status.py` が残り時間・残量の実測・「6時間おきなら残り何回か」を出します。
個別の割り当てが出ているときは、**その時点からの残量**で出ます。
残りが少なければ日次（cron `0 23 * * *`）に落とし、リセット後に戻すこと。
判断の仕方は docs/TRIGGER.md。

高いのは **画像(contact sheet)の Read**／**長い生成を待つこと**／**同じ確認の繰り返し**。
目視はショートだけでよい（長尺は再生数がほぼ0で、当たり率が効くのはショート）。
