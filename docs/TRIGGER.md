## 間隔を変える判断

**予算では決めない**（2026-08-08 に制限が外れた）。決めるのは**律速**。

- **6時間おきを維持する条件** — 判定材料が届くのが YouTube 側の都合で決まり、
  起きて待っても早まらない。かつ1日1本しか配信されない（`hypotheses.yaml` confirmed）
- **頻度を上げる条件** — 1日に複数本が配信されると分かったとき、
  または当たり率を上げる作業が「時間で買える」と分かったとき
- **頻度を下げる条件** — 分析しても変えることが無い回が続いたとき（B12）

**予算を理由に降格しないこと。** 2026-08-06 に換算のずれだけで日次へ落として
同日中に戻した。**往復そのものが無駄だった。**

## 落としても止まらない理由

**投稿が予約済みなら、起きなくても公開される。** だから間隔を落としても
チャンネルは動き続ける。逆に**予約が切れそうなときは、他を削ってでも生成に使う。**

`status.py` が「予約が入っていない日」を出すので、そこだけ見ればよい。

## やること

    python scripts/post_pending_comments.py
    python scripts/status.py

**分析は毎回。** 期限が来ている前提は必ず判定する（`config/hypotheses.yaml`）。
**しきい値は掛け算してから置くこと**（検出できない条件を反証条件にしない）。
読んだ結果を docs/JOURNAL.md に書く。動いていないなら「動いていない」と書く。

**作成と公開予定は任意。** 予約に空きがある／切り口を変えるべきと判断した、ときだけ。

    python -m src.pipeline --topic <ID> --dry-run       # ショートは --short
    python scripts/inspect_build.py <ID>                # contact sheet を作る
    python scripts/upload_only.py <ID>                  # 予約時刻は第3引数（ショートは 9）

**contact sheet の目視は Agent ツールの子エージェントに任せること。本流で Read しない。**

**目視をやめないこと。** 折り返しの機械検査（`src/visuals.py` の `render()`）は
「**ブラウザが指示どおりに折ったか**」しか見ていません。
**こちらが指示した位置そのものが悪い場合は素通りします**（2026-08-08、
「医療／費」がそれで通った）。機械と目視は**別のものを見ている**ので、両方要ります。

**子エージェントには動画の向きを伝えること。** 2026-08-08、56秒のショートを
長尺だと思い込んで横向きで検算し、目視の正しい指摘を「誤報」と結論しかけました。
縦（540x960・実効392px）と横（1280x720・実効1124px）では入る文字数が3倍違います。

画像は本流に入れると以後の全応答で再読され続ける（常駐セッションでは約10倍高い。
2026-08-05 実測: 子エージェント35Kトークン vs 本流300K超）。検査の質は落ちない
（判定一致・検算までやった）。子エージェントには6点の確認と「投稿可/作り直し」の
判定を7行で返させる。

`calc:` の無いテーマは台本生成が止まります（数字を発明させないため）。
生成は待たなくてよい。「生成中」と書いて終わり、次の回で拾う。
**背後の生成はコンテナ再起動で消える**ので、次回かならず予約一覧で確かめること。

最後に docs/JOURNAL.md へ追記して push。**変えなかったならそう書く。**
