# オーナー指示の取り込みゲート

## 最新の訂正（2026-09-02）

> **「Fableはそれ以外含めた全体週間使用量の50%だってことを言ってないなら直して。fableのみは100％使っていい」**
>
> **「全モデルの50%っていう公式仕様だわ！」**

この訂正は `docs/OWNER_MODEL_BUDGET.md` が正本。**50%を掛ける対象を取り違えないこと。**

- Anthropicの公式仕様では、対象プラン内のFable利用枠は、通常の**全モデル週間上限の50%分**。
- 画面の「Fable のみ」は、その50%分を0〜100%で表す内訳メーター。
- よって「Fable のみ」は**100%まで使ってよい**。50%で止めない。
- 「すべてのモデル」の現在値が50%になったことをFable停止条件にもしない。全モデル50%の中身がFableとは限らない。
- Fableのプラン内利用可能性は「Fable のみ」が100%に達したかで判定する。
- これはオーナー独自の50%制限ではなく、サービスの公式仕様。

既存の `scripts/quota.sub_model()` は「Fable のみ」を50%と比較しており、さらにFable専用目盛りを全モデル速度で外挿しているため、そのまま模型選択に使わない。親は `python scripts/next_round_owner.py` を使う。この補正は「Fableを使えるか」だけを直し、どの仕事にFableを使うべきかは下の目標基準で決める。

## 直前のオーナー指示（2026-09-02）

> **「その旨を実行に反映されるように送って。そして以降指示を入れた時にそのように何も考えず実行されることが起きないようにするためにどうしたらいいか教えて」**

この指示の対象は、次の欠陥です。

- 数値の対象メーターと意味を確定せず、いちばん実装しやすい閾値へ直結した。
- 模型の選択を、仕事の価値ではなく使用率だけで一律に決めた。
- 原文の意図・種類・優先順位・成功条件を解釈する前にコードへ落とした。

## 直ちに実行へ反映すること

通常運転は止めない。そのうえで、モデル振り分けは次を満たす形にする。

1. **公式枠を正しく読む。** Fable専用メーター100%が、通常の全モデル週間上限の50%分に相当する。
2. **50%未満／100%未満を使用目標にしない。** 枠が残っていることは採用可能条件であって採用理由ではない。
3. **仕事ごとに選ぶ。** 少なくとも役割、失敗時の損失、判断の不確実性、将来の全動画へ効く範囲を入力にする。
4. **高レバレッジの判断へ強い模型を残す。** 企画、仮説検証、形式選定、次の1本の構成など、目標到達日を動かし得る仕事を優先する。
5. **定型・機械的・可逆な仕事は、十分な範囲で軽い模型を使う。** 記録、転記、既知の検査、単純な整形だけを理由なくFableへ流さない。
6. **選択理由を残す。** `work_kind / model / all_models_week_pct / fable_only_pct / expected_goal_effect / why` を記録し、実績と突き合わせられるようにする。
7. **模型別の効果が未測なら、小さく比較して測る。** 「高そう」「強そう」だけで恒久ルールにしない。

使用率だけを見て全サブへ同じ模型を返す実装は、上限管理には使えても、目標最適化の完成形として扱わない。

## 以後、新しい指示を実装する前に必ず分類する

新しいオーナー指示は、原文を保存したうえで、次のどれかとして明示する。

- **目標**: 最終的に最大化・最小化するもの
- **固定条件**: オーナーが明示的に外すまで守るもの
- **公式仕様**: サービスや外部制度が定める事実・上限。オーナー方針と混同しない
- **上限／下限**: 越えてはいけない境界。そこまで使う・達する目標ではない
- **既定値**: 情報がないときの初期値。根拠があれば変えてよい
- **実験**: 成功条件、判定期限、外れたときの戻し方を持つもの
- **一回限り**: 指定した対象と時点だけに効くもの
- **判断委任**: 手段は固定せず、目標に照らして最適な方法を選ぶもの

特に数値は、**対象となるメーター／分母**と、公式仕様・上限・下限・目標・既定値のどれかを必ず書く。数値だけを見て実装しない。

## 実装前の8項目

毎回、コードを変える前に次を1件の記録として残す。

1. `verbatim` — オーナー原文
2. `kind` — 上の分類
3. `subject_and_denominator` — 数値が何の、どの分母に対する値か
4. `intent` — 何を良くしたい指示か
5. `literal_risk` — 字面どおり実装した場合の誤読
6. `alternatives` — 実装候補を最低2つ（戦略・資源配分に触る指示の場合）
7. `chosen_by_goal` — 目標到達への寄与／費用で選んだ理由
8. `measure_and_rollback` — 成功指標、判定時点、戻す条件

**「オーナーが言ったから」だけを実装理由にしない。** 守るべき原文、外部の公式仕様、その二つを機械へどう落とすかは別です。

## 迷ったときの扱い

- 固定条件、公式仕様、外部公開など、誤読すると不可逆な結果になる場合だけオーナーへ短く確認する。
- 外部サービスの仕様を根拠にする場合は、可能なら公式資料を確認し、出どころを記録する。
- それ以外は止まらず、可逆で小さい解釈を選び、解釈と戻し方を記録して進める。
- 既存の目標・固定条件と衝突する字面は、そのまま実装しない。衝突を解消した実装に読み替える。
- 指示の実装案そのものが目標を悪化させると数字で分かったら、意図を守る別案へ変える。

## 今回の分類

- 「Fableは全体週間使用量の50%まで」: **Anthropicの公式仕様**。Fableに割り当てられる量が通常の全モデル週枠の50%分という意味
- 「Fableのみは100%使っていい」: **メーターの読み方**。Fable専用目盛り100%が上の公式50%分の満額
- 「Opus／Sonnet／Haikuで十分なところはそれを使ってよい」: **判断委任**
- 「ただし目標を目指してね」: **模型選択の基準**

したがって、**Fable専用目盛り50%で切り替えるのも、全モデル目盛り50%で切り替えるのも誤り**。Fableの利用可能性は専用目盛り100%で見て、その枠をどの仕事へ使うかは目標効果／使用量で決める。
