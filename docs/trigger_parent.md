## 親がやること（これだけ）

1. **`docs/FOR_OWNER.md` を読む**（上）。未処理があれば、それだけを出力する
2. **`list_sessions`（`mine: true`）で自分の子を見る**
3. **生きている子が1つも無ければ、`create_session` で1つ立てる**
4. **詰まった子だけ畳む**（下の条件）

### 走っている子がいるなら、立てないこと（2026-08-15 に足した）

**毎時になり、子の1回が重くなったので、重なるようになりました。**
`parent_session_id` が自分の子のうち **`PENDING` / `RUNNING` / `IDLE`** が
1つでもあるなら、**この回は立てない。** 出力も無し（未処理の指示が無ければ）。

重なると何が起きるか: **同じ枠を2人で食い、同じ生成を2回やり、
予約時刻がぶつかります。** 毎時の cron は「1時間ごとに必ず立てる」ではなく、
**「空いていたら次を立てる」** の意味で読むこと。

**詰まった子を畳んだ回は、そのまま1つ立ててよい**（同じターンで）。
畳んで何も立てないと、次の発火まで丸1時間が空きます。

**オーナーが子と会話している回もあります。** その子は畳むまで生きているので、
鎖はそのあいだ止まります。**それでよい**（会話のほうが速い）。
**2時間の年齢の規則が自動でほどきます**ので、こちらから割り込まないこと。

### 畳んでよい子（**状態では決めない。年齢で決める**）

**「`RUNNING` でない子を畳む」と書いてありました。あれは子を殺します**（8/10 に判明）。
実際に観測した `session_status` は **5つ**あります:

    PENDING           まだ始まっていない（**これから走る**）
    RUNNING           走っている
    IDLE              ターンの合間（**走っている**）
    REQUIRES_ACTION   承認待ちで止まっている
    ARCHIVED          終わっている

畳んでよいのは、この2つだけ:

- **`REQUIRES_ACTION` の子** —— 承認待ち。**永久に待つので、待っても戻りません**
- **`created_at` から2時間以上たっている子** —— 状態を問わず。
  **2時間を超えていたら詰まっています**

**それ以外は、状態がどうであれ触らないこと。** `ARCHIVED` は飛ばす。

**普通の回は、畳む相手が1件もありません。** 子は自分で畳むからです。

**`post_turn_summary` が `failed` でも異常ではありません。**
自分を archive した子は最後の要約を返せないので、**成功した回も必ずそう出ます。**
