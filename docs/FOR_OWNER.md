### 1. 使用量の%を、**8/16 の昼ごろに1回だけ**（前回と同じ1行です）

**お願い**: 使用量の画面の**「週間の制限／すべてのモデル」の%と、見た時刻**を
親セッションに。例: `8/16 12:30 で 21%`。**5時間枠のほうはもう要りません**
（下の「済み」のとおり、こちらの API と対応が取れたので自分で追えます）。

**なぜ「昼ごろ」と時刻を指定するか**（前回は「いつでも」と書きました。**あれは
雑でした**）。2点の差から傾きを引くとき、**%が整数でしか読めないぶんの誤差が
差につきまといます** —— 1点 ±0.5%、差では **±1.0%**。いただいた2点の差は
3% だったので、幅が [2%, 4%] ＝ **区間の速さは [0.597, 1.194] %/時** に広がり、
**通算の 0.785 と区別がつきませんでした。**

    差が 3% のとき   誤差 ±1% は差の **33%**    → 通算と混ぜて使うしかない
    差が **8%** のとき 誤差 ±1% は差の **12.5%** → **区間だけで決められる**

**13% から 8% 増えるのは、いまの速さだと約10時間後**です。だから
「8/16 の昼ごろ」。**それより早いと、また混ぜることになります。**

**これで何が決まるか。** いま「1周あたり 41分あける」で回しています。
1周の重さの見立てが 0.333%（通算）と 0.500%（直近）で割れていて、
**前者なら 34分でよく、後者なら 52分要ります。** 3点目が入ればここが1つに決まります。
**短すぎれば 8/12〜8/14 に実際に起きた58時間の停止をもう一度踏み、長すぎれば
枠を余らせたまま週が終わります**（＝回せたはずの周を捨てる）。どちらも本数に直結します。

**自分で取る道は、この回に2つ試して2つとも届きませんでした。**
①`rate_limit_info` には % が入っていない（「開いている／警告／閉じた」と
リセット時刻だけ。今回もう一度実物で確認）。②`usage` のトークン数から
逆算する道 —— **1周ぶんが実測できたのは39周のうち3周だけ**で、
残り92%は値そのものが返っていません（この穴は塞ぎにいきます。塞がれば
**この依頼ごと不要になります**）。

**忘れていても構いません。** 41分のまま回り続けますし、投稿は 9/3 まで
予約が入っているので**止まりません。** 精度が上がるだけです。
