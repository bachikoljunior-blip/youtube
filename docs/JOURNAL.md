# 投稿の日誌

**追記だけ。過去の行を書き換えないこと。**

> 目標は `CLAUDE.md` にあります。**最短で月収20万。「最短」は理論値で、
> まだ発見されていないものとして扱う** —— つまり、ここに書かれた過去の判断も
> 「そのときの最善の推測」でしかありません。踏襲する義務はありません。

毎日の投稿は、常駐セッションに定期実行が撃ち込まれる形で回っています。そのセッションは
永遠には続きません。文脈が伸びれば要約されて薄れますし、いつか別のセッションに引き継ぐ
ことになります。

そのとき失われるのはコードではなく**判断の理由**です。何を試して効かなかったのか、
なぜその切り口をやめたのか、いつ何を変えたのか。YouTube 側は「何をいつ出したか」と
「どうなったか」しか持ちません。**「なぜそうしたか」を持つ場所がここです。**

## 書き方

1回の投稿につき数行。長さより、書いてあること。**見出しに自分のセッションIDを
書いてください**（システムプロンプトの Claude-Session の URL にあります）。

```
## 2026-08-05  (session_01AbCdEf...)
- …
```

書く価値があるのは、**数字を見ても分からないこと**だけです。何を出したかは
チャンネルに、成績はアナリティクスにあります。ここに要るのは、その数字を見て
何を考え、何を変え、何を変えなかったか。変えなかった理由のほうが、しばしば有用です。

**読むのは末尾10件ほどで足ります。** このファイルは伸び続けるので、全部読む必要は
ありません。古い記入が要るのは、いま触っている箇所の経緯を辿るときだけです。

## 毎回、必ず読み直すこと

**前回の記憶で動かないでください。** 同じセッションに撃ち込まれ続けるので、
「昨日これをやった」という感覚は残っています。その感覚は、日が経つほど薄れていく
一方で、薄れたことには気づけません。

だからいつも、このファイルとチャンネルの実績を読み直してから判断してください。
**1回の実行が独立していれば、このセッションは伸び続けても構いません。**

## 引き継ぐとき

乗り換えは、伸びたからではなく **セッションが落ちたとき** か、**別の環境に移すとき**
にだけ必要になります。手順は [`KICKOFF.md`](KICKOFF.md) にあります。

  「別の作業で試したが起動しなかったので止めた」と指摘され、痕跡を残す形で検証し直した。
  新規セッションに git へ push させる作業だけを投げ、20分待ってブランチが現れるかを見た。

  厳密には「起動しなかった」と「起動したが push できなかった」を切り分けていないが、
  オーナーの独立した経験と合わせれば前者と読むのが妥当。
  **教訓：自分の弱い観測で、オーナーの経験や日誌の記録を上書きしないこと。**
  この失敗が docs/GOAL.md の確認項目2の由来。
- **承認ダイアログの問題。** 環境が auto mode の分類器で動いていて、コマンドごとに
  個別判断されるため「常に許可」の選択肢が出ず、毎回聞かれる。これを止めるには
  .claude/settings.json に許可ルールが要るが、**エージェントが自分の権限を書き換える
  操作は分類器に拒否される**（正しい制限なので迂回しない）。オーナーに作ってもらう必要がある。
  オーナーが .claude/settings.json を作ってくれた。ただし**このセッションには効いていない。**
  確認方法：deny に入れた `printenv*` が通るかどうか。`printenv HOME` が通ったので
  効いていない。プロジェクト設定はセッション開始時に読まれるもので、このセッションが
  始まった時点で .claude/ が存在しなかったため。settings.json が入った状態で始まる
  セッションには効くはずだが、**この環境で実際に確かめてはいない。**

- **承認が出ていた主因は、設定ではなく書き方だった。** 拒否されたコマンドを並べ直すと
  全部が複合コマンドか環境変数の前置きだった（`ls ...; echo ...; cat ...` /
  `PYTHONPATH=... python ...` / `for t in ...; do ffmpeg ...; done` /
  `git add && git commit && for i in ...`）。許可ルールは**コマンド文字列の先頭への
  前方一致**なので、つないだものや前置きしたものは `Bash(ffmpeg *)` に一致しない。
  設定が効いていても分類器に回る。
  **次に来る側へ：コマンドは1行に1つずつ実行すること。** これだけで承認はほぼ出ない。

  verify も通っているので、作り直しに30分かける意味がない。
