# 手段の台帳 — 月20万に届きうる道を、全部ここに並べる

**これは `config/hypotheses.yaml` とは別のものです。**

    hypotheses.yaml … いまの機械（税金計算のYouTubeショート）を**どう良くするか**
    このファイル    … **そもそもどの機械に乗るか**

## なぜ要るか

2026-08-09 にオーナーから「恒久指示のあらゆる手段を使ってがうまく効いていない」と
指摘され、確かめたところ**そのとおりだった。**

`hypotheses.yaml` の9件が**全部「ショートの改善」だった。**
誘導の文言、冒頭の数字、投稿頻度、天井の有無。
**乗り物そのものを問うものが1つも無い。**

つまり私のループは「いまの機械を磨く」ことしかできず、**乗り換える経路が
設計に存在しなかった。** A13（あらゆる手段を実行してよい。これは許可ではなく指示）は
文書に書いてあっても、**それを実行に移す仕組みが無ければ効かない。**
「忘れないように書く」で解決しない、というのは A4 で何度も学んだはずのこと。

## 規則

1. **毎回 `scripts/status.py` がここの未着手件数を出す。** 目に入らないものは無くなる
2. **目標の数字（登録者・1日あたり再生）が2週間動かなかったら、
   次の回は「いまの機械の改善」をやってはいけない。** 未着手の手段を1つ進める
3. **却下するときは数字で理由を書く。** 「たぶん無理」は却下の理由にならない
4. **ここに書いていない手段を思いついたら、まず追記する。** 実行はそのあとでよい

## 手段の一覧

### M1. YouTube AdSense（いまやっている道）

- **状態**: 実行中
- **必要量**: 登録者1,000人＋直近12か月4,000時間 → その後 RPM¥1,000 なら月20万再生
- **実測からの距離**: 登録率 0.021%。1,000人に **480万再生**、1日800再生なら **16年**。
  ショート単独の門（90日で1,000万再生）は、いまの90日7.2万再生に対し **139倍**
- **評価**: **いまの規模では桁が足りない。** 改善しても2桁足りない
- **続ける理由**: 動いている資産で、止める費用もゼロ。他の手段の**素材**にもなる

### M2. 同じ動画を他のプラットフォームにも出す

- **状態**: **オーナーの操作が要る（2026-08-09 に確認）。自分だけでは始められない**
- **確かめたこと**: この環境の資格情報は `YT_CLIENT_ID` / `YT_CLIENT_SECRET` /
  `YT_REFRESH_TOKEN` / `GOOGLE_TTS_API_KEY` の4つだけ。
  TikTok・Instagram の類は**1つも無い**。
  投稿にはアカウント作成・開発者アプリ登録・OAuth が要り、**どれも人の手が要る**
- **扱い**: A1 は「私側への指示をしてもいいですが、それを私が必ず読むとは限りません」。
  **だから計画の柱にしない。** やってもらえたら上振れする「おまけ」として置く
- **オーナーへの依頼（読まれたら）**: TikTok か Instagram のアカウントを作り、
  投稿用のトークンを環境変数に入れてもらえれば、**以後の投稿は全部こちらで自動化できる**
  （動画は既にあるので追加費用はゼロ）
- **中身**: TikTok / Instagram リール に、**作った動画をそのまま出す**
- **追加費用**: ほぼゼロ（動画は既にある。投稿の自動化だけ）
- **なぜ効きうるか**: 新規アカウントへの配信の出方がYouTubeと違う。
  **同じ素材で配信面が3倍**になる。1本あたりの当たり率が同じでも、露出は増える
- **確かめること**: 各プラットフォームのAPI／自動投稿の可否、規約（他所への再投稿）
- **なぜ今までやらなかったか**: **理由が無い。** 単に候補として挙げていなかった

### M3. AdSense を通さない収益（1,000人の門を通らない）

- **状態**: 未着手
- **中身**: 計算そのものを成果物にする（有料の計算ツール、条件別の試算書など）
- **掛け算**: 月24,000再生 × 転換0.1% × ¥2,000 = **月4.8万円**。
  **いまの再生数のままでも成立しうる。** 目標には4倍足りないが、
  M1 の100倍足りないのとは**桁が違う**
- **注意**: このリポジトリの存在は出さない（B13）。商品側は別に立てる
- **確かめること**: 決済手段、景品表示・特商法の要件、税務の助言に当たらない線引き

### M4. 検索流入（YT_SEARCH がほぼ未開拓）

- **状態**: **実行中（2026-08-09 に着手）。自分だけで進められる唯一の手段。**

      YHiigJ3Zpj4  8/09 19:00  副業20万円ルールは経費を含む（副業 20万円 経費 含む）
      m_q1G_GNgY8  8/10 19:00  残業代 計算 手当 含まれないもの

  **`docs/SEARCH_TERMS.md` で「競合が薄い」と実測された語**から選んでいる
  （推測で題材を選んで長尺7本が0〜1再生だったのが、この手段の出発点）。
  3本目は `tenshoku-nenshu`（年収660万円 給与所得控除）を用意済み。
  **結果が出るのは検索に拾われてから。ショートと違って48時間では判定できない。**
  最初の判定は 8/16 ごろ、**お金に関係する検索語からの流入が
  1再生/7日（下の基準値）から動くか**で見る。**37 と比べない。**
- **実測**: 直近7日で YT_SEARCH は **37再生**（SHORTS は4,280）。
  **さらに悪い。28日ぶんの検索語を取ったら、お金の検索が1件も無かった:**

        11回  絶望ビリー カラオケ
         3回  草川兄弟
         1回  wii / いせん / お昼ご飯 夏休み / カズマランゲージ / バーテンダー 刀 / 右翼団体

  **全部このチャンネルの前身の名残。** チャンネル名・説明・キーワードは
  お金と税金で正しく設定されている（2025-09-01 開設・公開12本）のに、
  **こちらの題材では一度も検索に拾われていない**
- **測り直した（2026-08-09 夜）。上の読みは半分古い。**
  直近**7日**で引くと「絶望ビリー カラオケ」は**1回も無い**（名残は抜けた）。
  残る17再生は 草川兄弟・wii・家系ラーメン・橋本環奈 など**無関係な語**で、
  ショートが検索面に差し込まれているだけと考えられる。

      **お金に関係する検索からの流入 = 「手当」1回 / 7日。これが基準値。**

  **以後、検索の判定はこの 1再生/7日 と比べること。** 37 と比べない
  （あれは28日ぶんで、しかも大半が名残）。
  キーワードもこの日に在庫へ合わせて入れ替えた（13題材が抜けていた）
- **なぜ効きうるか**: 検索は**尾が長い**。ショートは48時間で完全に止まる（確認済み）が、
  検索流入は積み上がる。総再生時間4,000時間の門にはこちらのほうが効く
- **もっと大事な理由を、8/9 まで書いていなかった（追記）**: **登録率。**
  実測（直近90日）は **ショート 4,415再生で登録1人＝0.0227%、長尺は1再生で未測定。**
  ショートの率では1,000人に **440万再生**、1日800再生で**15年**。
  **律速は登録者なので、この率が変わらない限り M1 はどうやっても届きません。**
  長尺の登録率は**一度も測れていない**（既存長尺7本が0〜1再生で分母が無かった）。
  **つまり M4 は「総再生時間のため」ではなく「登録率を測り直すため」の手です。**
  9/15 を期限に反証条件を切った（`config/hypotheses.yaml`）。
  ここで1桁上がらなければ、**M1 に道は無いと確定**し、M3 へ移る。
- **確かめること**: 実際に検索されている語（キーワードの実測）。推測で作らない

### M5. RPM の高いニッチへ移る

- **状態**: 未着手
- **中身**: 同じ「計算して発表する」形のまま、単価の高い領域へ
- **掛け算**: RPM が10倍なら必要再生数は1/10。ただし **M1 の門は再生数で決まる**ので、
  門を通る前は効かない。**門を通ったあとに効く手**
- **評価**: 順番が違う。M1 の門を通す目処が立ってから

### M6. ChatGPT を使った競合調査

- **状態**: **済（2026-08-09）。** GitHub Actions の `chatgpt-ask.yml` 経由で実行
  （ローカルには `CODEX_AUTH_JSON` が無く直接は叩けない）
- **得られたこと**: **実測と一致した。** 「問題は結論を言ったことより、
  **結論直後に動画が再スタートすること**」。1枚目 stat →2枚目「計算の前提」が
  まさにその形で、5秒の落差の正体だった。他に「25〜35秒に圧縮」
  「1画面1情報・1〜2秒ごとの視覚変化」「完全静止画＋一定速度の音声＋全文字幕は不利」
- **ここから2つ実行した**: 2枚目の前提を機械で落とす検査、尺を50→30秒
- **中身**: 伸びている日本語の「お金」系ショートが、冒頭5秒で何をしているかを調べる
- **なぜ今やる価値があるか**: **5秒で落ちることが実測で分かった**（2026-08-09）。
  何と比べて悪いのかを、推測ではなく他所の実例で確かめられる
- **費用**: ほぼゼロ
