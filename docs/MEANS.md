# 手段の台帳 — 月20万に届きうる道を、全部ここに並べる

**これは `config/hypotheses.yaml` とは別のものです。**

    hypotheses.yaml … いまの機械（税金計算のYouTubeショート）を**どう良くするか**
    このファイル    … **そもそもどの機械に乗るか**

## なぜ要るか

2026-08-09、「あらゆる手段を使う」が効いていないのではないかと疑って
確かめたところ、**そのとおりだった。**

`hypotheses.yaml` の9件が**全部「ショートの改善」だった。**
誘導の文言、冒頭の数字、投稿頻度、天井の有無。
**乗り物そのものを問うものが1つも無い。**

つまり私のループは「いまの機械を磨く」ことしかできず、**乗り換える経路が
設計に存在しなかった。** A13（あらゆる手段を実行してよい。これは許可ではなく指示）は
文書に書いてあっても、**それを実行に移す仕組みが無ければ効かない。**
「忘れないように書く」で解決しない、というのは A4 で何度も学んだはずのこと。

## 2026-08-10 追記 — 台帳を作っても、掛け算しなければ意味が無かった

**この台帳は8/9に作ったのに、8/10まで「門の先」を一度も掛けていなかった。**
M1 の必要量の欄に書いてあったのは
「登録者1,000人＋4,000時間 → その後 RPM¥1,000 なら月20万再生」。
**この文の後半は、長尺のRPMをショートの機械に当てたもの。**
ショートの RPM（¥50〜150）を掛け直すと**月990〜2,970円**にしかならない。

**手段を並べただけでは選べない。桁を出して初めて並ぶ。**
以後、**状態・中身・掛け算の3つが揃っていない項目は
「未着手」ではなく「未評価」**として扱うこと。
数えるだけの台帳は、`hypotheses.yaml` が9件ぜんぶショート改善だったのと
同じ壊れ方をする。**数えることと評価することは別。**

## 規則

1. **毎回 `scripts/status.py` がここの未着手件数を出す。** 目に入らないものは無くなる
2. **目標の数字（登録者・1日あたり再生）が2週間動かなかったら、
   次の回は「いまの機械の改善」をやってはいけない。** 未着手の手段を1つ進める
3. **却下するときは数字で理由を書く。** 「たぶん無理」は却下の理由にならない
4. **ここに書いていない手段を思いついたら、まず追記する。** 実行はそのあとでよい

#### 何を源にするか —— **表どうしの組**（`gassan` が唯一の実例）

#### 測ったこと1 —— **引数の名前で繋ぐのは無理**（この回の実測・否定側）

#### 測ったこと3 —— **既知の当たりが、入力の軸では1件も入らない**（**この手段の最大の穴**）
